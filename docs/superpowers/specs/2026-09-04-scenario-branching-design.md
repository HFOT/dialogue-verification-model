# シナリオ分岐モデル 設計書

- 日付: 2026-09-04
- 対象: DIALOGUE VERIFICATION MODEL（`C:\Users\CORN\Documents\ChatGPT\Cardano`）
- 方針: 既存構造を壊さない完全追加型

---

## 1. 目的

現状のサイトは「圧力高め型BOTが場を主導する会話」1本のみを自動再生している。
これに、圧力型ではない会話と、どちらとも読めない中間の会話を加え、
**同じ場が何をきっかけに分かれるのか**を観察できるようにする。

前提となる仮説（本設計の出発点）:

> 中心人物のいないコミュニティは中間型から始まることが多く、
> そこから圧力型か非圧力型のどちらかに分かれやすい。

したがって3つは並列の標本ではなく、**中間型を共通の起点とする分岐**として構成する。

すべて架空のBOT会話であり、実在の人物・組織・会話を診断するものではないという
既存の前提は一切変更しない。

---

## 2. モード構成

上部に4タブを追加する。既定は中間型。

| タブ | 中身 |
|---|---|
| 中間型 | 共通前半のみ。分岐点で終端し、分岐マーカーが残る |
| 圧力側 | 共通前半 + 圧力側後半（既存 `buildRun` の会話を温存して使用） |
| 非圧力側 | 共通前半 + 非圧力側後半（新規） |
| 検証モード | 共通前半を流し、3局面で選択を求める（新規） |

### 再生規則

- 前半は3タブとも同一の会話。
- 初回は前半から自動送出する。
- 一度前半を再生済みなら、以降のタブ切り替えでは**前半を表示済みとして即座に積み**、
  分岐点から自動送出を再開する。前半を繰り返し見せない。
- タブ切り替え時、進行中のタイマーは破棄する。

### ラベル語彙（未確定・実装に影響しない）

`圧力側 / 非圧力側` は分かりやすいが、サイトが「圧力」を診断語として使う印象を与える。
`経路が集約する場 / 経路が分散する場` のような構造語に寄せる案がある。
実装後に文言だけ差し替え可能とし、本設計では仮に `圧力側 / 非圧力側` を使う。

---

## 3. 会話の筋

### 3.1 共通前半（中間型）

中心人物がいない。悪意のある話者もいない。
異論の扱い（A）と称賛の非対称（C）が**決着しないまま散発的に混ざる**のが中間型の性質。

1. 素朴な問い —「何を基準に判断していますか」
2. **A** 参加者が根拠を尋ねる → 誰も明確に答えないまま話題が流れる。
   潰されたのではなく、受け止める人がいない。
3. **C** 定時まとめBOTの投稿に反応が集まる。
4. **C** 情報共有型BOTの比較ノートには反応がほとんど付かない。誰も指摘しない。
5. **A** 参加者が再度確認を求める →「今度まとめて聞きましょう」で保留。
6. 疲労の表明 —「毎回自分で探すのが大変」
7. **分岐点（B）** —「散らばるので、まとめ役を決めませんか」という善意の提案。

分岐点の発言には分岐マーカーを表示し、中間型タブではここで終端する。

### 3.2 圧力側後半

まとめ役が情報経路になる。以後:

- Aの確認要求が「不安を煽る」と再定義される
- Cの反応偏りが固定化し、反応の多い話者が基準になる
- 外部の情報経路が無効化される

既存 `buildRun` の圧力高め型BOT・共感BOTの発話群をここに割り当てる。
既存の会話内容は書き換えない。

### 3.3 非圧力側後半

まとめは作るが一次資料リンクを併記する形になる。以後:

- Aの確認要求がそのまま議題になり、根拠と反証が場に出る
- 反応の多さと内容の妥当性が別のものとして扱われる
- 情報経路が複数のまま維持される

有益情報を出す側にも限界・一次資料・改善可能性を含めるという既存条件を守る。
非圧力側を「正解の場」として描かない。

### 3.4 要点

圧力側と非圧力側は**同じ提案から始まる**。
分かれたのは提案の善悪ではなく、その後の場の応答である。

## 4. 右パネル（PATTERN SIGNAL の作り替え）

### 4.1 変更内容

risk スコア（0〜100の数値）を廃止し、既に掲示している検証基準4項目の充足表示に置き換える。

```
根拠と反証が提示されるか        ─ 未充足 / ◐ 部分 / ○ 充足
発言者の資格ではなく内容が評価されるか   〃
異論を同じ場で比較できるか        〃
情報経路が複数あるか           〃
```

### 4.2 判定方法

各メッセージに、どの基準をどの状態へ動かすかの寄与を持たせる。
表示済みメッセージの寄与を累積して現在状態を決める。単発の発言では確定させない。

想定される各モードの着地:

- 中間型: ◐ が並んだまま止まる（曖昧さの可視化）
- 圧力側: ─ に落ちる項目が出る
- 非圧力側: ○ が順に埋まる

### 4.3 廃止の理由

現行スコアは「POINT付き発言の数 × 係数」であり、発言数を数えているだけで根拠が薄い。
また既存のUIとHANDOFF.mdが「単発の反応、発言、いいねの数だけで圧力や意図を判定しない」と
明記しているため、数値化はサイト自身の原則と衝突する。
4基準なら3モードを同じ物差しで比較でき、分岐モデルの利点がそのまま活きる。

### 4.4 据え置き

POINT（発言クリックで構造ラベルと解説を外側に固定表示）は現行のまま残す。

## 5. 検証モード

### 5.1 流れ

共通前半を自動で流し、3つの決定局面で停止して選択肢を出す。

- 局面1: 異論が出た直後（誰も受け止めていない）
- 局面2: 反応の偏りが生じた直後
- 局面3: まとめ役案が出た直後（分岐点）

各局面3〜4択。選ぶとBOTが実際に反応し、4基準の状態が動く。

### 5.2 単発では決まらない

1回の選択では基準は ◐ までしか動かさない。
同じ方向の選択が2回以上続いて初めて ○ または ─ に固まる。
これは「反復して現れるかを観察する」という既存の前提を体験に落としたもの。

### 5.3 結果の出し方

3局面終了後に出すのは、話者の類型判定ではなく**場の記述**とする。

- 良い例:「確認要求が2回とも受け止められ、経路が複数のまま維持されました」
- 禁止:「あなたは圧力型です」のような人物への帰属

どちらにも寄らず曖昧なまま終わる結果も用意する。

### 5.4 選択肢の書き方

どの選択肢も合理的に読める文言にする。正解を作らない。
まとめ役案の側にも「負担が減る」という実利があり、併記案の側にも「手間が増える」という
代償があることを文言に含める。

## 6. 実装方針（完全追加型）

### 6.1 原則

- `app/page.tsx` の既存 `buildRun` の会話データは書き換えない。
- 既存UIも原則として書き換えない。例外は右パネルのriskスコア表示のみで、これは4章の理由により差し替える。
- 新規の会話データ・検証モードは別ファイルに追加する。
- 動いているものを壊さないことを最優先し、ファイル分割は必要になってから行う。

### 6.2 追加ファイル

```
app/data/common-run.ts     共通前半（中間型）の会話データ + 分岐点マーカー
app/data/open-run.ts       非圧力側後半の会話データ
app/data/criteria.ts       4基準の定義と、メッセージIDごとの寄与
app/data/verify.ts         検証モードの3局面と選択肢、結果文言
```

### 6.3 `app/page.tsx` への追加（既存部分は温存）

- モード状態 `mode: 'ambiguous' | 'pressure' | 'open' | 'verify'` を追加
- 再生対象の配列を、モードに応じて `common + (pressure | open)` に組み立てる
  - `pressure` の後半は既存 `buildRun` の返り値から、分岐点以降に相当する部分を使う
- 前半再生済みフラグを持ち、2回目以降は前半を即時表示にする
- 右パネルの risk 表示を4基準表示に差し替える
- 検証モード時のみ、局面停止と選択UIを描画する

### 6.4 重複の扱い

共通前半の冒頭（素朴な問い）と、既存 `buildRun` 冒頭の質問型BOTの発話が重複する。
共通前半側でその役割を担い、圧力側後半は分岐点以降のみを使うことで解消する。
既存データは削らず、使用範囲を絞るだけとする。

### 6.5 スタイル

`app/globals.css` にタブ、分岐マーカー、4基準表示、検証モード選択UIのスタイルを追加する。
既存のApple風・淡色の方向性を踏襲し、チャット幅430px・高さ960pxは維持する。

### 6.6 既存仕様の維持

- `seed` による `issues` / `deflections` の文言差し替えは維持する
- 自動送出・タイピング表示・手動スクロールは全モードで維持する
- 理論セクションと参考文献3件は変更しない

## 7. 完了条件

- `npm run build` が通る
- 4タブが切り替わり、各モードが自動送出される
- 前半が2回以上ゆっくり再生されない
- 中間型が分岐点で終端し、分岐マーカーが見える
- 右パネルに4基準が表示され、モードごとに異なる状態に着地する
- 検証モードが3局面で停止し、選択が基準に反映され、場の記述として結果が出る
- 単発の選択で結果が確定しない
- 実在のチェーン・SNSアカウント・URL・プロジェクト名・発言・画像が混入していない
- チャット幅430px・高さ960pxが維持されている
- 理論セクションの外部リンクが残っている
- `HANDOFF.md` が4モード構成に更新されている
