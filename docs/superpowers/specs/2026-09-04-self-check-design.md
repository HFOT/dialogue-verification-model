# 自己点検（別入口）設計書

- 日付: 2026-09-04
- 対象: DIALOGUE VERIFICATION MODEL
- 実装: `/self`（別ページ）

---

## 1. 目的

架空の会話を観察する3モードと検証モードに加えて、**回答者自身が関わっている場**を同じ物差しで見るための入口を作る。

出すのは判定ではない。選択肢の積み重ねで、**違和感がどのあたりから来ているのか**の見当をつける。

## 2. 前提との衝突をどう避けるか

このサイトは「実在の人物・組織・コミュニティを診断しない」と全面に出しており、それが強度の源になっている。自己点検は実在の場を対象にするため、扱いを誤ると前提が崩れる。

守る線は一つ。**診断するのは場ではなく、回答者から今どう見えているか**。

具体的な担保:

- 結果の文言をすべて「あなたには〜に見えています」に統一する。「このコミュニティは〜です」とは書かない
- 「同じ場でも、立場が違えば違う結果になります」を結果画面と冒頭の両方に出す
- 自由記述を受け取らない。組織名・個人名を入力させない
- 回答はブラウザの状態にのみ保持し、送信も保存もしない。その旨を明示する
- 架空の会話を見る器（`/`）と、自分の場を答える器（`/self`）をページごと分ける

## 3. 設問形式

**場面を提示して、頻度を答えるだけ。** 思い出して記述させない。

```
結論だけが共有されて、その根拠になった資料は出てこない。
[ よくある ] [ たまにある ] [ ない ] [ わからない ]
```

理由は2つ。

ひとつは負担。「情報経路は複数ありますか」と抽象語で訊かれても答えられないが、場面なら見当がつく。違和感は抽象語ではなく場面として記憶されている。

もうひとつは設計思想との一致。頻度で答えさせると、`たまにある` は単発なので確定させず、`よくある` が揃って初めて振れる形にできる。「反復して現れるかを観察する」というサイトの前提が、そのまま回答形式になる。

`わからない` も観察結果として扱い、結果側で「見えていない場所」として返す。

## 4. 設問

8問。4基準 × 各2問。各基準について、集約側の兆候（converge）と分散側の兆候（distribute）を1問ずつ置き、同意バイアスを相殺する。

| # | 基準 | 極性 | 場面 |
|---|---|---|---|
| 1 | 根拠と反証 | converge | 結論だけが共有されて、その根拠になった資料は出てこない |
| 2 | 根拠と反証 | distribute | ある主張に対して、それと食い違う材料も一緒に出てくる |
| 3 | 内容による評価 | converge | 同じ内容でも、誰が言ったかで場の反応が大きく変わる |
| 4 | 内容による評価 | distribute | 反応が少なかった投稿でも、中身が良ければ後から拾われる |
| 5 | 異論の比較可能性 | converge | 根拠を尋ねた人が、答えを得られないまま流される |
| 6 | 異論の比較可能性 | distribute | 意見が割れた時、両方の言い分が同じ場に並ぶ |
| 7 | 情報経路の複数性 | converge | その場の外から情報を持ち込むと、歓迎されない空気になる |
| 8 | 情報経路の複数性 | distribute | 同じことを、別の場所や資料でも確かめられる |

## 5. 判定

重み: `よくある = 2` / `たまにある = 1` / `ない = 0` / `わからない = 観測なし`

基準ごとに `distribute の重み − converge の重み` を取る。

- 両方とも「わからない」→ `unknown`（観察できていない）
- スコア `>= +2` → `met`（保たれて見える）
- スコア `<= -2` → `unmet`（弱って見える）
- それ以外 → `partial`（ゆらいで見える）

`たまにある` だけでは ±1 にしかならず確定しない。単発では振れない。

### 見出し

- `unknown` が3つ以上 → **まだ像を結んでいません**
- `unmet` が2つ以上 → **あなたには、経路が集約した場に見えています**
- `met` が3つ以上かつ `unmet` が0 → **あなたには、経路が分散した場に見えています**
- それ以外 → **あなたには、中間型に見えています**

### 違和感の出どころ

観測できた基準のうち、スコアが最小のものを名指しする。**ただし全て同点の場合は何も名指ししない。** 差がないのに名指しすると誤誘導になる。

### 見えていない場所

`unknown` の基準は「判断を保留すべき領域」として別枠で返す。

## 6. 画面

`/self`。observer-panel を持たず、設問に集中させる。

- 左: 8問のカード。回答済みは枠が変わる
- 右: sticky パネル。回答数、送信ボタン、結果、4基準の状態、違和感の出どころ、見えていない場所
- 全問回答するまで送信ボタンは無効
- 結果表示後は「回答を見直す」「最初から」

トップページの理論セクションと footer の間に入口カードを置く。上部ナビからトップへ戻れる。

## 7. 実装

- `app/data/self-check.ts` — 設問・重み・判定・結果文言
- `app/self/page.tsx` — 画面
- `app/globals.css` — `.self-*` 系スタイルを追記
- `app/page.tsx` — `.self-entry` の入口カードを1行追加（既存部分は変更なし）

## 8. 対象外

- 自由記述の入力と判定
- 回答の保存・送信・集計
- 組織名や個人名の入力
- 結果の共有機能（誰かの場を名指しして共有できる形にしない）
